Slice — "ritagliare" porzioni di lista

La notazione lista[inizio:fine:passo] ti permette di prendere qualsiasi sottoinsieme di una lista in una sola riga. È uno degli strumenti più usati quando lavori con batch di dati o finestre temporali.

python — slice in azione
losses = [2.5, 1.8, 1.2, 0.9, 0.7, 0.5, 0.4, 0.3]

# Prendi le prime 3 losses (epoch iniziali)
inizio = losses[:3]      # → [2.5, 1.8, 1.2]

# Prendi le ultime 3 (epoch finali)
fine = losses[-3:]       # → [0.5, 0.4, 0.3]

# Prendi ogni 2 (un sample ogni 2 epoch)
ogni2 = losses[::2]      # → [2.5, 1.2, 0.7, 0.4]

# Inverti la lista
inversa = losses[::-1]   # → [0.3, 0.4, 0.5, ...]

# Estrai un range specifico
middle = losses[2:6]     # → [1.2, 0.9, 0.7, 0.5]
Perché è importante nel ML

Quando hai un dataset di 10.000 immagini, potresti voler prendere solo le prime 80% per il training e le ultime 20% per la validazione. Con lo slice: train = dataset[:8000] e val = dataset[8000:]. Due righe, nessun loop.

Filtrare con list comprehension e condizioni

La list comprehension con filtro è il modo pythonista per creare nuove liste a partire da quelle esistenti, applicando una condizione. La sintassi è [espressione for elemento in lista if condizione].

losses = [2.5, 99.9, 1.2, 0.9, -0.1, 0.7, 150.0, 0.5]

# Filtra i valori anomali (outlier)

Array NumPy — la differenza con le liste Python
Perché non basta Python puro?

In Python puro, sommare due liste di 1 milione di numeri richiede un ciclo for da 1 milione di iterazioni. NumPy fa la stessa operazione in una sola chiamata a codice C ottimizzato — 100-1000x più veloce. Quando alleni una rete neurale, stai sommando milioni di numeri migliaia di volte. La velocità non è un lusso.

python — array e operazioni fondamentali
import numpy as np  # convenzione universale: sempre "np"

# Creare array
a = np.array([1.0, 2.0, 3.0, 4.0])
b = np.array([2.0, 2.0, 2.0, 2.0])

# Operazioni VETTORIZZATE — agisce su ogni elemento
print(a + b)      # → [3. 4. 5. 6.]  (non serve un ciclo for!)
print(a * b)      # → [2. 4. 6. 8.]
print(a ** 2)     # → [1. 4. 9. 16.]  (quadrato di ogni elemento)

# Array speciali utili
np.zeros((3, 4))   # matrice 3×4 di zeri  (utile per inizializzare pesi)
np.ones((2, 3))    # matrice 2×3 di uni
np.arange(0, 1, 0.1)  # [0.0, 0.1, 0.2, ..., 0.9]
np.random.randn(3, 3)  # matrice 3×3 da distribuzione normale
Shape e matrici — il concetto chiave del deep learning

Nel deep learning tutto è una matrice (o un tensore, che è una matrice multidimensionale). Un'immagine 28×28 pixel in bianco e nero è una matrice 28×28. Un batch di 64 immagini RGB 224×224 è un tensore di shape (64, 3, 224, 224). Capire le shape è il 50% del debug in PyTorch.

Un vettore è semplicemente una lista ordinata di numeri. Ma la sua forza sta nell'interpretazione geometrica: un vettore [3, 4] rappresenta un punto nello spazio 2D, o una freccia che va dall'origine a quel punto. La lunghezza di quella freccia è la norma (o magnitudine) del vettore.

python — vettori con NumPy
import numpy as np

# Vettori 2D (facili da visualizzare)
u = np.array([3, 4])
v = np.array([1, 2])

# Operazioni base
print(u + v)        # → [4, 6]  (somma componente per componente)
print(2 * u)        # → [6, 8]  (scala il vettore)

# Norma (lunghezza del vettore)
norma = np.linalg.norm(u)   # → 5.0  (teorema di Pitagora: √(3²+4²)=5)

# Prodotto scalare (dot product) — misura la "somiglianza"
dot = np.dot(u, v)          # → 11  (3×1 + 4×2)

# Coseno dell'angolo tra vettori (similarity in NLP!)
cos_sim = np.dot(u, v) / (np.linalg.norm(u) * np.linalg.norm(v))
print(f"Cosine similarity: {cos_sim:.3f}")  # → 0.982
Cosine similarity nel linguaggio naturale

In NLP, ogni parola viene convertita in un vettore (embedding). La cosine similarity misura quanto due vettori "puntano nella stessa direzione". "Re" e "Regina" hanno cosine similarity alta (~0.85). "Re" e "Pizza" hanno cosine similarity bassa (~0.1). Così GPT capisce che parole hanno significato simile.

Una derivata misura la pendenza di una funzione in un punto. Se la derivata di f(x) in x=3 è 2.0, significa: "se aumento x di 1, f(x) aumenta di circa 2". Nel ML, la funzione è la loss e le variabili sono i pesi del modello. La derivata ci dice: "se aumento questo peso, la loss sale o scende?"

python — derivata numerica approssimata
# Funzione loss semplice: L(w) = (w - 3)²  (minimo in w=3)
def loss(w):
    return (w - 3) ** 2

# Derivata numerica: (f(x+h) - f(x)) / h  con h molto piccolo
def derivata(f, x, h=1e-5):
    return (f(x + h) - f(x)) / h

# Proviamo in vari punti
for w in [0, 1, 3, 5]:
    grad = derivata(loss, w)
    direzione = "↑ aumenta" if grad > 0 else "↓ diminuisce"
    print(f"w={w}: loss={loss(w):.1f}, grad={grad:.1f} ({direzione})")
# w=0: loss=9.0, grad=-6.0  (devo aumentare w)
# w=3: loss=0.0, grad=0.0   (minimo! gradiente = 0)
# w=5: loss=4.0, grad= 4.0  (devo diminuire w)
L'analogia della montagna

Immagina di stare su una montagna in una fitta nebbia. Non vedi dove sei — senti solo il terreno sotto i piedi. Per scendere a valle (trovare il minimo della loss), segui la pendenza: se il terreno scende a sinistra, vai a sinistra. Il gradiente è la pendenza. "Gradient descent" = scendi seguendo la pendenza. Il learning rate determina quanto grande è ogni passo.

Gradient descent in azione
python — ottimizzazione con gradient descent
def loss(w):       return (w - 3) ** 2
def grad_loss(w):  return 2 * (w - 3)  # derivata analitica di (w-3)²

w = 10.0            # partenza lontana dal minimo
lr = 0.1            # learning rate

print(f"Inizio: w={w:.2f}, loss={loss(w):.2f}")

for step in range(1, 11):
    gradient = grad_loss(w)
    w = w - lr * gradient  # il cuore di gradient descent
    print(f"Step {step:2d}: w={w:.4f}, loss={loss(w):.4f}")
# Step  1: w=8.6000, loss=31.36
# Step  5: w=4.3046, loss= 1.749
# Step 10: w=3.1074, loss= 0.012
# → converge verso w=3 (il minimo!)

La probabilità di un evento è un numero tra 0 e 1 che misura quanto è plausibile quell'evento. P=0 significa impossibile, P=1 significa certo. La probabilità congiunta P(A e B) misura la probabilità che accadano entrambi. La probabilità condizionale P(A|B) misura la probabilità di A sapendo che B è già accaduto.

python — probabilità con NumPy
import numpy as np

# Simulazione: lancio di un dado 10000 volte
np.random.seed(42)
lanci = np.random.randint(1, 7, size=10000)

# P(dado = 6)
p6 = np.mean(lanci == 6)
print(f"P(6) = {p6:.3f}")   # → ~0.167 (cioè 1/6)

# P(dado pari)
p_pari = np.mean(lanci % 2 == 0)
print(f"P(pari) = {p_pari:.3f}")  # → ~0.5

# P(pari E > 3) — probabilità congiunta
p_pari_gt3 = np.mean((lanci % 2 == 0) & (lanci > 3))
print(f"P(pari AND >3) = {p_pari_gt3:.3f}")  # → ~0.333 (4 e 6)

# P(>3 | pari) — condizionale: sapendo che è pari, P che sia > 3?
pari = lanci[lanci % 2 == 0]  # solo i pari: 2, 4, 6
p_cond = np.mean(pari > 3)    # dei pari, quanti sono > 3?
print(f"P(>3 | pari) = {p_cond:.3f}")  # → ~0.667 (4 e 6 su 2,4,6)
Il teorema di Bayes — aggiornare le credenze con i dati

Il teorema di Bayes dice: P(A|B) = P(B|A) × P(A) / P(B). In italiano: "la probabilità di A dato B, è proporzionale alla probabilità di B dato A moltiplicata per la probabilità iniziale di A". La probabilità iniziale si chiama prior, quella aggiornata si chiama posterior.

Esempio spam detector

P(spam) = 0.2 (il 20% delle email è spam — il prior). P("Vinci subito" | spam) = 0.8 (80% degli spam contengono questa frase). P("Vinci subito") = 0.05 (solo il 5% di tutte le email contiene questa frase). Allora P(spam | "Vinci subito") = 0.8 × 0.2 / 0.05 = 3.2... ma le probabilità non possono superare 1! Normalizziamo: P = 0.16 / (0.16 + 0.04) = 0.80. Ovvero: vedendo quella frase, la probabilità spam sale dal 20% all'80%.

python — Naive Bayes spam detector
# Probabilità prior
p_spam   = 0.2  # il 20% delle email è spam
p_nospan = 0.8  # l'80% non è spam

# Probabilità likelihood (P di ogni parola dato spam o non spam)
parole = {"vinci": (0.8, 0.01), "caro": (0.7, 0.3), "grazie": (0.1, 0.6)}
#              (P se spam, P se non spam)

def naive_bayes(email_parole):
    score_spam = p_spam
    score_ok   = p_nospan
    for parola in email_parole:
        if parola in parole:
            score_spam *= parole[parola][0]
            score_ok   *= parole[parola][1]
    totale = score_spam + score_ok
    return score_spam / totale

email = ["vinci", "caro"]
print(f"P(spam) = {naive_bayes(email):.1%}")  # → ~96%

Overfitting: il modello ha memorizzato i dati di training invece di imparare pattern generali. Funziona benissimo sui dati che ha visto, ma fallisce su quelli nuovi. È come uno studente che ha memorizzato le risposte senza capire le domande.

Underfitting: il modello è troppo semplice per catturare i pattern nei dati. Sbaglia sia sul training che sul test set. È come uno studente che non ha studiato abbastanza.

python — rilevare overfitting con train/val split
import numpy as np

# Training history simulata di un modello che overfita
train_loss = [2.5, 1.8, 1.2, 0.8, 0.5, 0.3, 0.2, 0.1]
val_loss   = [2.6, 1.9, 1.4, 1.1, 1.0, 1.1, 1.3, 1.6]

for epoch, (tr, val) in enumerate(zip(train_loss, val_loss), 1):
    gap = val - tr
    stato = "⚠ OVERFITTING" if gap > 0.5 else "✓ OK"
    print(f"Epoch {epoch}: train={tr:.1f} val={val:.1f} gap={gap:.1f} {stato}")

# Trova la best epoch (val loss minima)
best = np.argmin(val_loss)
print(f"\nBest model: epoch {best+1} (val_loss={val_loss[best]})")
# → Best model: epoch 5 — dopo di lì il modello overfittava
Early stopping

In PyTorch e Keras puoi usare il callback EarlyStopping che ferma automaticamente il training quando la validation loss smette di migliorare. Così non devi indovinare il numero giusto di epoch — il modello si ferma da solo al momento ottimale.

Cross-validation — valutazione robusta

Dividere i dati in un solo train/test split è rischioso: potresti avere fortuna (o sfortuna) con quella specifica divisione. La k-fold cross-validation divide i dati in k gruppi, allena k volte usando ogni gruppo come test set una volta, e fa la media dei risultati. Più affidabile, più costoso.
